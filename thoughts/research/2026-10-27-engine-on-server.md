# Исследование: движок правил на сервер своего стола

Дата: 2026-10-27. Этап 1 (bulletproof), только чтение, код не менялся.
Задача: перенести движок `tigris-bot/engine` на сервер сайта `tigris-euphrates-online`, клиент сделать рендером состояния движка, бот посадить за стол как место. Видео позже.

## 1. Что есть сейчас

### Сайт `tigris-euphrates-online` (GitHub denilis/tigris-euphrates-online, main = origin/main)
- `server.js` (359 строк, CommonJS, Express + Socket.io 4): комнаты по 6-значному коду, хост стартует, приватные руки (`your_hand`), широковещательный `game_state`. Правила игрушечные: ферма только на реку, конфликты «убрать тайл» вручную, очки кликами, катастрофы не работают, монумент в одну клетку без проверки 2x2.
- `index.html` (1160 строк, один файл, vanilla JS, Socket.io через `io()` с того же сервера): НЕ ЗАПУСКАЕТСЯ. `calcCS` объявлена дважды (строки 490 и 861), вторая присваивает `CS` во время инициализации `let CS = calcCS()` (496): ReferenceError на старте, весь скрипт мёртв. В закоммиченной версии то же (534 и 905). Рабочая копия содержит 202 незакоммиченные строки правок. `index2.html` (старая локальная версия) не парсится (экранированные обратные кавычки вне строк, 392-393, 401, 490).
- Модель игрока в клиенте и сервере перевёрнута: игроку назначен цвет, а лидеры именуются символами. В настоящей игре наоборот: игрок = династия (лев, лук, кувшин, бык), лидеры = 4 цвета. Ассеты `assets/tokens/{symbol}_{color}.jpg` (16 штук) покрывают правильную модель.
- Река и храмы в клиенте и сервере выдуманы (две прямые реки в рядах 2 и 10, `RIVER`/`SHEDU_S` продублированы в трёх файлах). Подложка `assets/board/field.png` нарисована «по-художественному», реки гуляют через клетки, выровнять нельзя. Настоящие карты есть в `tigris-bot/engine/boards.js`.
- Ассеты пригодны целиком: 6 тайлов, 16 жетонов лидеров, 6 монументов, 5 кубиков, фон лобби. Не используются: `terrain.png`, кубики, `unification.jpg`.
- `node_modules` неполный (нет `express`): `npm install` в папке Google Диска с кириллицей падает (известно по esbuild, который живёт в `~/.tigris-tools`).
- ТЗ (`TigrisOnline_ТЗ.docx`, март 2026) писалось до движка: «правил нет, честное слово, видео встроено». Этот принцип устарел.

### Движок `tigris-bot/engine` (ES-модули, 126 тестов, реплей 120 партий BGA: счёт совпал 120/120)
Контракт для сервера (строки по `engine/engine.js`):
- Состояние `createState({layout, numPlayers, cfg, monuments?})` / `createGame(opts, rng)`: плоский объект, без Set/Map/функций, но поля `river, special, tile, leader, treasure, building, monument` это типизированные массивы (Uint8Array/Int8Array). `JSON.stringify` превращает их в объекты `{"0":..}`. Для хранения и отправки: `Array.from`, обратно `T.from` (пример `test/fixes.test.js:99-102`). `cloneState` делит `cfg/river/special` по ссылке и сбрасывает `log`.
- Поля: `players[]` = `{hand[4], leaders[4], cats, score[4], treasures, discarded[4]}`; `bag[4]` счётчики по цветам (добор случайный в момент добора); `removed[4]` включает ПРИВАТНЫЕ сбросы; `cur, actionNo (1|2), turn, phase, toMove, ctx, over, endReason ('bag'|'treasures'), log`.
- `legalMoves(s)` (304-347) по фазам: `action` {tile,leader,withdraw,catastrophe,discard,pass}; `warChoose` {warColor}; `warSupport`/`revoltSupport` {support n}; `build` {build pos | pass}; `monument` {monument id tl | wonder center | pass}; `treasure` {treasure pos}; `wonderPoint` {wonderPoint color}; `over` [].
- `applyMove(s, m, rng)` (384-423) меняет `s` на месте, возвращает undefined, НЕ ПРОВЕРЯЕТ легальность (неизвестный ход в build/monument = пас). Сервер обязан сверять ход с `legalMoves` (как `sim/arena.js:31-34`, через JSON.stringify). После хода `advance()` крутит `ctx.queue` до следующего решения.
- Кто решает: `s.toMove`. Восстание: сначала атакующий, затем защитник (защитник видит `attN`). Война: при нескольких цветах `warChoose` у `cur`; атакующий = `cur`, если участвует, иначе следующий по кругу; поддержка атакующий, потом защитник. Здание/монумент/очко чуда: `cur`. Сокровище: владелец зелёного лидера в царстве с 2+ сокровищами (может быть не текущий игрок). Порядок после тайла: войны, здание, монумент, сокровище. Пас на 1-м действии заканчивает весь ход. Сброс добирает сразу.
- `rng` = функция `() => [0,1)`, нужна только в `drawTiles`. Ботам давать ОТДЕЛЬНЫЙ rng, иначе их раздумья меняют добор.
- События: `s.log = []` собирает `{type: tile|leader|withdraw|catastrophe|discard|unite|warStart|war|revolt|score|leaderReturned|building|monument|wonder|treasure|gameOver}` (как `sim/arena.js:23,43-46`). Основа журнала для клиентов.
- Конец: мешок пуст при любом доборе (даже посреди действия) или 2 и меньше сокровищ на поле при `nextTurn`. `finalVector` (932), `ranking` (948); при полной ничьей без флага (устойчивая сортировка по местам).
- `validate(s)` (957-1000): 153 тайла в сумме, лидеры не на реке и рядом с храмом, фермы только на реке, монументы на перевёрнутых тайлах. Годится как assert после каждого `applyMove`.
- Опции `cfg`: `englishSupport`, `buildings`, `wonder`; продвинутое поле = `BOARDS.advanced`; «открытый счёт» в движке нет, это настройка показа (BGA опция 104).
- Поле: индекс `i = y*16 + x`, `cellName(i)` даёт «D2» как на BGA.

### Бот `tigris-bot/bot`
- Вид бота: `makeView(s, me, counting, rng)` (`bot/belief.js:38-61`): чужие руки и сбросы обнулены, мешок обнулён, чужой счёт по `counting` (none/approx/exact). Утечка: `view.state.removed` остаётся сырым (с чужими сбросами); в клиентский payload `removed` сырым не отдавать, только `publicRemoved`.
- `decide(view, settings, rng)` / `decideAsync(view, settings, rng, defer)` / `decideGen`: возвращают `{move, text, error, ms, ...}`, `move` один ход из `legalMoves`. Бюджет поиска в фазе action `400 + 7000*strength/100` мс (до 7,4 с), остальные решения быстрые. На сервере считать в `worker_threads`, иначе Socket.io замирает.
- Настройки: `strength 0-100, counting none|approx|exact, risk 0-100, errors 0-30, style base|universal|top|denis|andrey|vlad|mix`, плюс `reply, depth, search:'mcts', catReserve`. Значение по умолчанию в коде `style:'base'`, в README написано universal (решение Дениса 22.10: по умолчанию «Универсальный»).
- Запасной ход при таймауте есть: `adapter/actions.js:95-109 safeMove(s)`.

## 2. Кто уже решал похожее
- boardgame.io (лобби, playerView для скрытой информации, боты, Socket.io): последний релиз 0.50.2 около 4 лет назад, активности нет. Его модель фаз конфликтует с собственными `phase/toMove/ctx` движка, пришлось бы оборачивать. Не берём.
- BGA решает ту же задачу на PHP с состояниями-машиной; наш движок уже устроен так же (`phase/toMove`), т.е. сервер нужен тонкий.
Вывод: писать свой тонкий сервер поверх движка эффективнее любой рамки: комнаты и Socket.io уже есть, движок уже машина состояний.

## 3. Рекомендация архитектуры
1. Сервер: `server.js` переводим в ES-модули, игровую логику целиком заменяем движком. Сервер держит полное состояние, принимает `move` от места `toMove`, сверяет с `legalMoves`, применяет, прогоняет `validate` (assert), рассылает каждому месту СВОЙ вид (своя рука и сбросы, счётчики чужих рук, `bagTotal`, `publicRemoved`, счёт по правилу стола) плюс события из `s.log`.
2. Места: человек или бот. У бота свои настройки (стиль, сила, подсчёт, риск, ошибки) и свой rng. Решение бота в `worker_threads`, результат проверяется так же, как ход человека. Запасной ход `safeMove` при ошибке.
3. Движок и бот в репозитории сайта: копировать `engine/` и `bot/` скриптом `tools/sync-engine.js` из `tigris-bot` (деплой Railway собирает из репозитория сайта, ему нужны файлы внутри). Исходник правды остаётся `tigris-bot`.
4. Клиент переписать (старый мёртв): лобби с опциями стола, экран партии = рендер состояния + панель решений. Поле SVG из `boards.js` (проба показана 27.10, реки точные). Ассеты старые.
5. Переподключение: токен места в localStorage, вход по коду и токену возвращает своё место. Снимок стола в JSON на диск после каждого хода (типизированные массивы через `Array.from`).
6. Таймауты и сдача: не в первом этапе, но `safeMove` оставить как механизм.

## 4. Открытые вопросы для спецификации
- Где живёт движок: копия скриптом (рекомендую) или сайт переезжает внутрь `tigris-bot`.
- Хранение партии на Railway (диск эфемерный): том Railway или смириться с потерей при рестарте в первой версии.
- Минимальный размер экрана: планшет в альбомной ориентации (1024 px) да, телефон нет.
- Открытый или закрытый счёт по умолчанию (на BGA партнёры играли с открытым).
- Видео: этап 3 как в ТЗ, пока звонок в Telegram.

## 5. Риски
- Поиск бота до 7,4 с на сервере: только через worker, иначе фризы.
- Типизированные массивы в JSON: один забытый `Array.from` ломает снимки и клиент.
- `applyMove` без проверок: любая дыра в сверке = читерство/поломка состояния. Сверка обязательна, тест на неё обязателен.
- Сокровище и защита решаются не текущим игроком: клиент должен уметь «сейчас решает не тот, чей ход».
- Конец партии посреди действия (мешок пуст при доборе после сброса).
